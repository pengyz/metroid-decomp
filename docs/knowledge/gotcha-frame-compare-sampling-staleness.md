# gotcha：双腿逐帧对拍三陷阱

## 现象

逐帧状态对拍（TD 仪器法，见 pattern-dual-leg-frame-state-compare.md）中三类**假结论**：

1. **采样缝错位**：emu 腿 `sample_point=endFrame`、rust 腿 spin-exit 缝——两腿行相位
   差一整窗，多帧工作被 endFrame 拦腰切断。表现为"TD 相位差 N 帧"的地图实为
   **约定错位+真实分歧的叠加体**——直接当施工图即错。
2. **陈旧产物**：任一腿代码变更后未重跑生成，对拍读的是旧二进制/旧流程的行。
   表现为"分歧地图"反映的是已不存在的代码态（r9 会话曾误用 spin=2 时期 rust 产物
   引发一轮混乱）。
3. **空字段集（假零分歧）**：字段键缺失（未 watch/键名错）时，逐字段比较的交集
   为空或恒等 ⇒ "0 分歧"的**假绿**。空 watch 集的逐帧比较恒返回零分歧。

## 为什么

- 双腿采样点在帧内位置不同（emu lua 帧界 vs rust spin 出口缝），同一 wall-frame 的
  状态在两侧行序列中可能差一拍——逐帧差分**必须先声明同缝**再比较；
- 对拍输入的生命周期绑定生成时刻：任一腿的代码/用例变更后，旧行集合即失效；
- 空集/缺键比较在多数实现里静默通过（无行可比=无差异可报）——**假零分歧是静默的**。

## 何时使用

- 任何跨腿逐帧对拍前：核对 run.json 的 `sample_point` 与 watch 键清单非空；
- 提取脚本必须**显式断言**字段存在（缺键=报错，不静默跳过）；
- 代码变更（rust/emulator 任一）后：**先重跑双腿生成，再提取**——禁止复用旧产物。
