# gotcha：未装载态探针空跑比对（实验条件错误类）

**现象**：写点级探针实录「触摸槽仅 boot 清零、从未填充」→ 归因「UpdateItems 提前
退出=结构性判死」→ 后被装载态实验推翻（槽每帧实填 289 轮）。探针跑未进目标
状态（道具房未达、道具未装载）——**门 0（Type=$FF）早退**下的一切观测都是
「空转面」。

**教训**：
1. **负结果先验实验前提**：「X 从未发生」必须先证「发生 X 的条件全部就位」——
   本例的条件=道具装载（PowerUpType≠$FF），探针跑没满足；
2. **判别实验要双态**（装载/未装载对照）——单态探针无法区分「机制死了」vs
   「机制没到场」；
3. **观测与机制的层错**：观测到「槽空」是对的，归因「机制不填槽」错了——
   观测≠归因，中间需要一个「条件就位证明」步骤；
4. 「精确重叠不触发」类负结果要查**比对对象是否在场**（本例 v12 跑=未装载态，
   比对的是空气）。

**适用域**：一切探针/插桩负结果归因（RAM 写点、回调触发、trace 缺行）。
**关联**：gotcha-sampling-point-is-blind-spot（同为观测盲区类）。
