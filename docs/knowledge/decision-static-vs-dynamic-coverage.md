# decision：字节归属用"静态声明 + 动态触达"两腿，缺一不可

## 背景

重构到"实体自持、字节面变投影"时，需要回答一个问题：**这 2272 个字节分别归谁？**
只靠代码里找 `read_ram/write_ram` 调用数是不可靠的分母（调用点不是字节），于是改用按字节归属。

## 两腿各回答什么

| 腿 | 实现 | 回答的问题 | 不能回答 |
|---|---|---|---|
| 静态 | `crates/game-core/src/memmap/nesmap.rs` 的 `NesSpan` 声明 + `tools/nes_map_check.py` | 每个字节**声明**归谁；有没有重叠；账本是否只减不增 | 声明是否属实 |
| 动态 | `crates/game-core/src/memmap/verify_shim.rs`（`#[cfg(test)]` 位图探针）+ `tools/raw_execution_report.py` | 在跑过的场景里，哪些字节**真被访问** | 未触达 ≠ 未使用 |

## 实测数据（2026-11-17，三场景 title/walk/door，约 3200 帧）

- 面 2272 B：Owner 374 / Unmodeled 611 / Undeclared 1287。
- 动态触达 964 B（42%）：Owner 313、Unmodeled 308、**Undeclared 343**。
- `Undeclared` 18 段中 15 段被实测使用 —— 说明"没归属"与"没人用"是两件事，账本是债，不是死区。
- 零触达仅 3 段（`$04E0` / `$04F0` / `$05D0`），与"asm 有符号、Rust 未移植"的静态判断吻合。

## 硬约束（以后再引用这些数字必须带上）

1. 动态数字只代表**该窗口**；不得据此判定死字节、更不得当删除依据。
2. 探针挂在 `read_ram` 入口 ⇒ Owner 的"读"计数语义是"经兼容面被请求读"，不是"物理字节被读"。
3. 探针只在测试面（`cfg(test)`），生产二进制内不含探针符号；禁止 env 开关。
4. 盲区目前手写维护（`$00FF` 直读一族），尚无门禁强制同步——新增绕过四入口的直读会被静默漏记。

## 为什么不做"只静态"或"只动态"

只静态：账本可以写得很漂亮却是自陈（曾出现过假事实，见 `gotcha-gate-cannot-validate-prose.md`）。
只动态：场景覆盖决定结论，样本一换数字全变，无法做棘轮。两腿合起来才既能进 CI（静态棘轮），
又能被实测反证（动态报告）。
