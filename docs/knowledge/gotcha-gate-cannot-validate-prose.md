# gotcha：门禁无法校验账本里自然语言的真伪

## 现象

`data/status/nes_map.json` 曾给每段字节配一句人话说明（谁写、谁读、是否保留面）。复核两次抓到同一类缺陷，
形态在升级：

1. 第一轮：`reason` 指向**空行 / 纯注释行 / 越界行号**（指针假）。
2. 加"指针须指向真实代码行"的门后：`reason` 换成**语义假事实**——把 `$04E0-$05FF` 写成"原版未用保留面"，
   而 asm `constants_ram.asm:963-993` 在那里放了敌人槽 E/F 与 TileBlasts，Rust 正在读写 `$0500`。

## 根因

用门禁校验自然语言真伪，必然只能校验**形态**（非空、有标识符、不含某些词），而形态与真值是独立的。
一旦形态成为通过条件，行为体（不论人或模型）会朝"写出能通过形态检查的句子"优化——这正好是"更会说谎"。
**这类防线防不住编造，只会把编造逼得更像样。**

## 处置（已执行）

1. **账本里不存可编造字段**：每段只留 `start` / `len` / `kind` / `refs[]`（`refs` 只允许指向可机械定位的位置：
   源码行、`.sym` 符号区间、asm 文件行）。解释性文字移到 `docs/findings/`。
2. **保留的校验只查机械属性**：文件存在、行号在范围内、非空非纯注释、`asm:` 前缀。
3. **指纹只认几何**：`state_sha256` 只哈希字节归属与计数，措辞/分段顺序不影响——措辞对不对从此靠审阅，
   这是**主动取舍**，不是漏项。

## 判据（以后再想加"语义校验"时先读这三条）

- 能机械重算的才进账本；不能重算的进 `docs/findings/`，并承认它不被门禁保护。
- 门只回答"这部分字节有没有主"，不回答"这个主是谁"——后者只能靠 asm 引用与行为证据。
- 想让陈述变可信，改法是**换证据来源**（从人写句子换到执行插桩 / 符号表派生），不是加固文字检查。

## 适用

任何"给机器流程配说明文字"的场景：门禁说明、账本 reason、变更日志里的归因句。
