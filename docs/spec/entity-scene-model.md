# 实体–场景模型（typed 实体的边界、引用与访问规则）

> 状态：**进行中**。本文先钉「实体是谁、场景是什么、它们怎么互相看见」，再据此决定跨域动作函数归位。
> 前置文档：[typed-domain-migration.md](../findings/typed-domain-migration.md)（typed 域迁移机制）、
> [core-state-machine.md](core-state-machine.md)（三轴状态机）。

## D-01 Samus 的身份：独立实体，暂时按 0 号槽别名实现

**决策**：长线目标里 Samus 是**独立个体**；当前按「对象池 0 号槽的类型化别名」实现。

**理由**：ROM 的 16 槽池是 NES 的存储布局约束，不是领域约束——Samus 与门、子弹共用同一套
绘制/离屏删除/`PageIndex` 机制，但语义上它不是"一个对象"，而是玩家本体（有装备、血量、
动画状态机、独立的输入通道）。保真期必须沿用同一套池机制（否则行为不等价），现代化期可以
让 Samus 脱离槽编号。

**因此订三条纪律**（缺一条，「别名」就会固化成耦合）：

1. **地址算术只在 `crates/game-core/src/samus/state.rs` 内出现**。crate 内任何其它文件都不得
   写 `0x0300 + n` 或假设 Samus 在 0 号槽；访问一律 `mem.samus()`。
2. **槽步长只在池类型内出现**。`16` 这个步长只允许出现在 `ObjectPool` / `EnemyPool` /
   `ExplosionPool` 的实现里，不得出现在业务代码（`slot_of()` 是唯一换算入口）。
3. **API 不暴露槽号**。公开面是 `scene.samus()`；`scene.object(0)` 若要返回 Samus 视图，必须是
   池内部的显式转换，不得让调用者"知道 0 就是 Samus"。

守住这三条，将来把 Samus 移出池只需改一个文件；守不住，它会像今天的 `$0316` 一样散落 6 处。

## 一、实体清单

| 实体 | 地址 | 规模 | 不变量 | 已 typed |
|---|---|---|---|---|
| `Samus` | `$0300-$0316` | 23 B | 状态↔动画↔半径自洽；速度四元组 | **全 23 字节** |
| `Object`（通用槽） | `$0300 + i*16`，i=1..15 | 15×16 B | 同槽内 obj 字段自洽 | 否 |
| `Enemy` | `$0400 + j*16` / `$6AF4 + j*16`，j=0..11 | 12×32 B | status↔动画↔半径；`$0406` 三名同格 | 前 7 字节 |
| `Explosion` | `$04C0 + k*8` / `$6BB4 + k*8`，k=0..3 | 4×16 B | status=0 表示空槽；`inc` 即占用 | 否 |
| `Title` | 标题屏专用 | — | 相位机自洽 | 标签→地址表 |

槽位分工（保真期的硬件布局）：0 号=Samus，8–11=门，12–15=子弹，1–7=其余对象。

**敌域的聚合根是「池」而不是单只敌人**：分配、`RemoveEnemy`、跨槽扫描、同帧互斥都是池级
不变量。`scene.enemy(j)` 只是池成员句柄，不承担"我这一槽自洽"之外的保证。

## 二、场景（Scene）

NES 没有场景对象，但**跨帧存活的世界状态**是明确的一组：

```
Scene
├─ room     房间 RAM 缓冲（WRAM $6000-$67FF，三块由 $37/$38 游标与 $39/$3A 基址选择）
│            + 房号 + 门表 + 道具状态
├─ camera   ScrollX/ScrollY/MapPosX/MapPosY/SamusScrX/SamusScrY + nametable 镜像与属性表
├─ objects  16 槽对象池（含 Samus@0、门、子弹）
├─ enemies  12 槽敌池
└─ explosions 4 槽爆炸池
```

`Manager` 在其上再加 `storage`（NES 字节存储）、`regs`（PPU/APU 寄存器面）、建模旗
（`deferred_screen_on` 等）。层次是 **storage（字节）→ scene（世界）→ entity（实体）**，
与 asm 的"硬件 / 世界 / 对象"三层同构。

## 三、引用关系

采用**场景持实体、实体是从场景借出的句柄**（不采用全局注册表，理由见
`typed-domain-migration.md` §6：需 unsafe/RefCell、丢静态类型、毁测试并行）。

```
impl Scene {
    fn samus(&mut self) -> Samus<'_>;                       // 独占，短生命周期
    fn enemy(&mut self, j: usize) -> Enemy<'_>;
    fn samus_and_enemy(&mut self, j: usize) -> (Samus<'_>, Enemy<'_>);  // 地址不重叠 ⇒ 安全分借
}
```

分借成立的依据是**地址不相交**：`Samus`(`$0300-$0316`) 与 `Enemy`(`$0400+`) 无交集；
同一池内两槽地址也不相交。因此「子弹打敌人」「敌人撞 Samus」有安全出口，不需要 unsafe。

**借用互斥是特性而不是障碍**：同刻只能一个实体可变，正好对应 6502 单线程的顺序执行；
当两个域的数据必须同时变化时，那是**系统函数**（下节第三层）的事，不是实体的职责。

## 四、跨域动作的三层归位

| 层 | 签名形态 | 可见范围 | 例子 |
|---|---|---|---|
| 实体方法 | `impl Samus { fn f(&mut self) }` | 自己 + 只读场景 | 跳跃弧线、球反弹、动画推进 |
| 实体对实体 | `fn f(scene: &mut Scene)` | 两个池（分借） | 子弹命中敌人、敌人撞 Samus |
| 系统 | `fn f(scene: &mut Scene, frame: u32)` | 全部 | 房间滚动、门过渡、换区 |

判据是**「这次变化的发起者是谁」**，不是「谁读写得多」：发起者留在自己方法里，被动方通过
系统；两方必须同时改才成立的，进系统。

### 已实测的分档（`crates/game-core/src/samus/` 37 个自由函数）

| 档 | 定义 | 数量（估计） | 处理 |
|---|---|---|---|
| 一 | 顺序复合：先 A 域再 B 域，无数据耦合 | ~8 | 直接拆，成本低 |
| 二 | 读写耦合，但可用返回值/入参解耦 | ~9 | 改参数传递，成本中 |
| 三 | 交错共享时序（含 `Temp00-$0F` 中转） | ~5 | **不拆**，留系统层 |

**反对第三档拆分**的判据是一条机械规则：**若拆分后必须重排 asm 的执行顺序才能编译，即停止**
——那是第三档，收益为负。`physics.rs::collision_point_ok`（跨 6 个地址族）是典型：
候选块坐标在两个域之间来回暂存，拆开反而更难证明等价。

另有 4 个函数属于**归错域**（与拆分无关）：`scroll_left/right/up/down` 属相机域、
`vertical_span_cols`/`horizontal_span_rows` 属房间域、`doors_remove_if_offscreen`/
`move_out_door` 属门域。它们的处理优先级最高——纯搬家，零行为风险。

## 五、访问规则与禁止项

允许：

- 实体方法内 `self.mem`（= `Scene`）的**只读**访问；
- 实体方法内经 `&mut *self.mem` 穿透到**系统函数**（有明确 asm 锚时）；
- 系统函数用 `scene.samus_and_enemy(j)` 分借两个池。

禁止：

- 跨帧持有实体句柄（`let s = scene.samus();` 活过一帧）——句柄是借用，不是所有者；
- 从实体方法返回内部 `&mut`（破坏独占性）；
- 在业务层出现槽步长 `16` 或实体基址（见 D-01 三纪律）；
- 用"再加一个 `&mut Manager` 参数"的方式绕开分借（那会把边界重新抹平）。

## 六、迁移顺序与止损

1. **实体清单与访问矩阵**（本文件）——纯只读，不含代码改动；
2. **`Scene` 类型落地**：把 `room`/`camera`/三池从 `Manager` 收进 `Scene`，`Manager` 只剩
   `storage + scene + regs`；此步不改任何行为（矩阵须逐格不变）；
3. **`Samus` 的 `&mut Manager` 收窄为 `&mut Scene`**——兑现"实体只看见世界、看不见硬件"；
4. **按访问矩阵逐档搬**：先归错域的 4 个，再第一档（每 3 个跑一次矩阵），第三档不动。

**止损条款**：第 2 步若两周内无法做到"矩阵逐格不变"，则承认 `Scene` 拆分收益不足，
退回"`Manager` 即场景"的现状，并把精力转回行为验证（100% 录像对拍）。

## 七、与既有门禁的关系

- `no-raw-addr`：裸地址字面量只减不增（现 779 处 / 25 文件），保护 D-01 纪律 1；
- `no-named-addr`：`ram_map::SAMUS_*` 等具名常量绕过面只减不增（165 处 / 6 文件）；
- 两者都**不**检查槽步长与基址，纪律 2 暂时靠 review 与本文约束；若日后出现漂移，
  再补 `no-slot-stride` 门（先记在案，不提前建）。
