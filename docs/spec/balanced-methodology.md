# 平衡方法（轻量设计+正常推+强复核）

> 【2026-10-22 用户裁定】认可，把规则落地，后续按此推动——1:1 Rust 改写（平衡方法）。

## 核心判断

1:1 改写是确定性任务（asm 函数→rust 函数（确定性映射））——**不需要过度设计**（映射是确定性的）——**但实现正确性需要测试/验证**（这是我们应该 focus 的地方）。

## 一、平衡方法（3 层）

| 层 | 方法 | 目的 |
|---|---|---|
| **轻量设计** | 函数/数据结构级映射（确定性（不需要过度设计）） | 拿到正确映射（但不过度设计） |
| **正常推** | TDD（测试先行（实现后补）） | 快速实现（迭代改进） |
| **强复核** | 对抗复核（11 项（必跑验证）） | 保证质量（实现正确性） |

## 二、轻量设计（函数/数据结构级映射（确定性））

**轻量设计**（函数/数据结构级映射）：
1. asm 函数→rust 函数（确定性映射（不需要过度设计））
2. asm 数据结构→rust struct（确定性映射（不需要过度设计））
3. asm 数据表→game-data（确定性映射（不需要过度设计））
——映射是确定性的（不需要过度设计）——拿到映射就实现

## 三、正常推（TDD（测试先行（实现后补）））

**正常推**（TDD）：
1. 写测试（穷举等价证明（全域穷举（边界条件（异常路径））））
2. 跑测试（cargo test（实测输出原文（A 级）））→失败（实现未完成）
3. 写实现（真规则（公式形（零字面特值）））
4. 跑测试（cargo test（实测输出原文（A 级）））→通过（实现完成）
5. 重构（优化实现（保持测试通过））
6. 复核（对抗复核（11 项（必跑验证）））

## 四、强复核（对抗复核（11 项（必跑验证）））

**强复核**（对抗复核）：
①六步流程是否走通？②refs 引证是否实址？③域结构是否正确？④memmap 适配是否正确？⑤shim 写集适配是否正确？⑥测试是否充分？⑦registry 登记是否完整？⑧实现是否包含真规则？⑨测试是否穷举等价证明？⑩复核是否实际运行验证？⑪验证轨迹和实现是否对等？
任一缺 = needs_revision（拒收）

## 五、timer 检查项（9 项）

①list_agents（派满纪律）②git log（仓内定损）③git 提交状态检查（区分漏提交 vs 在产）④进度检查（完备性文档）⑤依赖图检查（是否按顺序推进）⑥对抗复核检查（每步完成后是否派独立 agent）⑦收敛判定（337 地址命名函数=0）⑧处置待件（微工单纪律）⑨台帐完整性检查（是否更新了（是否有错误或者漏了））
