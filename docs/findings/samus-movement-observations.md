# findings：Samus 移动观测（G4 首切片证据基础，2026-10-14）

## 已证实（A 级）

### A1 入局前提审计——「卡死态」现象与可靠解锁序列
- **卡死态**：`start@360 + a@420` 之后画面冻结在「无精灵房间」帧（像素全同：smoke f500 =
  samus-move f550/600/660 = sha `8cbf4a35…`），且**无限期持续**（samus-move2：f700–f1140 四帧全同）。
- **解除**：追加一次确认输入（samus-move `start@540` / smoke `start@480+a@540`）后 ~150–200 帧
  出现 Samus 精灵（samus-move OAM 变化自 f687）。`start@360 + a@420 + start@540` 序列可复现解锁。
- **对照**：samus-move2（无追加确认）1200 帧始终卡死 ⇒ 追加确认是必要条件（3 次实验对照）。
- 注：卡死态画面身份（密码屏残帧 vs 出生前房间态）**未定谳**——列为待证（见 C 组）。

### A2 d-pad 输入链路无故障
- `tools/scenario_capture.lua` 埋 `emu.setInput` pcall 探针（键名无效会静默失败）：samus-move3
  全程 **无失败记录** ⇒ `right/left` 键名有效、输入已送达。
- 场景 DSL `hold` 时刻表注入正确（PLAN 字面量核验：holds right 850-1150 / left 1180-1330 在列）。

### A3 行走/穿门实证（像素级）
- `samus-move3`：f800 起始房间（Samus 立于桥）→ f1150 **右行 300 帧后画面全变**（新房间、
  敌人精灵、HUD 可见）⇒ 右行穿门成立；f1330 左行后画面再变（diff 18891px 全屏级）。
- 早期「转身不走」伪结论（samus-move f720 vs f870 diff 仅 x120-135 居中 16×32 精灵框）
  **修正**：该窗口为解锁前/出生保护期，输入仅触发动画/翻面，不代表移动语义。

### A4 移动反应面（正确时间窗，2KB RAM 全观测）
- 静止窗 f780–840 vs 移动窗（右行 f860–1140 / 左行 f1190–1320）：**339 个地址**响应移动
  （静止窗仅 15 个变化）——A 级「移动可观察面」建立。
- 样例轨迹（idle@780 → right 末@1140 → left 末@1320）：
  `$0000: 00→89→19`、`$0011: 15→89→19`（同轨迹，疑影子/双份）、`$0008/$0009: 00,04→5D,5D→C4,C4`
  （成对同值变化，疑指针）、`$000E: 80→8F→70`、`$0004: 00→1B→17`。
- 完整面数据：`analysis/traces/samus-move3.frames.jsonl`（zp+iram 逐帧 hex，可复现）。

## 假设（C 级，未证不得引用为结论）

- H1 卡死态画面 = 密码屏残帧/出生前房间态（待截屏对照密码屏已知形态或 trace 定谳）。
- H2 `$0000/$0011` 同轨迹 = 疑 Samus 水平位置或其影子（**未证**：右行窗含穿门/换房搅动，
  需单房间内纯行走窗 + 逐帧相关性分离）。
- H3 `$0008/$0009` 成对变化 = 疑 16 位指针（房间/门数据？）。
- H4 第三次确认输入的语义 = 「空密码提交开局」（vs 暂停恢复——两者行为预测不同，待证）。

## 对 G4 的直接影响（spec 写作约束）

1. 移动 spec 的动态证据必须取自 **解锁确认后 ≥800 帧** 的窗口（前置窗口数据不可用）；
2. 房间切换搅动必须与单房间纯行走窗分离（否则位置变量辨识被换房数据污染）；
3. 「入局序列」本身应进 spec（R-boot-* 规则）：`title→start→A→start` 才到可操作状态。
