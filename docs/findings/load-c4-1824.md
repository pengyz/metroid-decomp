## 0 结论（总 work 与 trace 逐点相等＝A；逐对象分配＝B）

**1824 = 2 × `LOAD_MT_FAST`(214) + 4 × `LOAD_MT_FULL`(349) = 428 + 1396。**

不是某个对象或某个累加项被整项跳过，而是**元 tile 个体**在绘制期被两条 ROM 机制少画了 6 个：

| 机制 | ROM 位置 | 触发对象 | 少画 | 折算周期 |
|---|---|---|---|---|
| 行边界提前换行（`RoomRAMWorkPtr & $1F == 0`） | `prg7_engine.asm:9853-9858`（`@else_roomLeft`/`@endIf_roomLeft`） | obj2（pos=`$09`，struct=`$11`，palette1=fast） | 2 fast | 428 |
| 属性区守卫 `rts`（指针进入 `$63C0` 起属性区） | `prg7_engine.asm:9784-9809`（`@DrawMetatile`→`@checkLowByte`） | obj13（pos=`$B0`，struct=`$0B`） | 2 full | 698 |
| 同上 | 同上 | obj14（pos=`$BE`，struct=`$0B`） | 2 full | 698 |
| **合计** | | | **2F+4U** | **1824** |

数量口径：**16 对象 / 46 行 / 140 元 tile（按流计）→ 实际画 134 元 tile（68 fast / 66 full）**。
57240（上界）与 55308（实测）的 1824 差在这 6 个元 tile 上闭合。

**证据分级（不要混）**：
- **A 级**：`(55308, 31446, 36620, 43378)` 四组「模型总 work = trace 读数」逐点相等——这是外部观测对模型的整体验证。
- **B 级**：§2 那张 16 对象的分配表（obj2 少 2 fast、obj13/obj14 各少 2 full）是**模型内部归因**，没有逐对象的 `DrawObject` 入口计数 trace 支撑。它可信是因为总量精确闭合到 55308 且五条候选都被排除，但**不是观测事实**。
- 若要升 A：在 `DrawObject`/`DrawStructRow` 入口插只读探针，逐对象记 `(入口次数, 实画元 tile 数)`，采房 `$18` 一次载房窗，与 §2 表逐行对账；届时 obj2=15F、obj13/14=8U 才算实测。

## 1 机制（asm 原文）

`DrawObject` 对每个对象 `jsr DrawStruct`（`prg7_engine.asm:8797`）；`DrawStruct` 用
`jmp DrawStructRow`（`:9880-9890`）进入行绘制，行尾又落回 `DrawStruct` 处理下一行。
因此行绘制内部的 `rts` 会**返回到 `DrawObject`**（`jsr DrawStruct` 的下一条），即**该对象剩余结构整段停画**。

- 属性区守卫（`:9784-9809`）：`lda Temp00_RoomRAMPtr+1 / cmp #>(RoomRAMA+$03C0) / ... / rts`，
  命中 `hi=$63` 且 `lo≥$A0` 时 `rts`（注释：「Can't draw any more of the structure, exit.」）。
- 行边界提前换行（`:9844-9859`）：每画完一个元 tile 后 `lda Temp00_RoomRAMPtr / and #$1F / bne @else_roomLeft`；
  为零时把 `Temp0E_MetatileCounter-1` 加进结构索引，**跳过本行剩余元 tile**直接进下一行。

两条机制都不报错、不影响行计数（行头已消费并累加 `LOAD_ROW`），只减少实画元 tile 数。

## 3.5 与 #132 §2.1 的口径冲突及更正

**本文推翻 #132 的「守卫不触发」结论**：`docs/spec/room-load-cycles.md:124` 写「`$6000` 缓冲最大行指针 `$6392` vs 阈值 `$63A0` ⇒ 否（不触发）」，那只算了**结构起点**的行指针；本文按逐对象、逐元 tile 的轨迹算，obj13 的写指针到 `$63C0`、obj14 到 `$63DC`，都越过 `$63A0` ⇒ **守卫确实触发两次**。`#132` 该段是错的（同一作者两版模型，后来者为准）。

数值反证（同一脚本改一处假设即可复现）：若把守卫当**行级**（只丢本行剩余元 tile、继续下一行）而不是结构级（`rts` 返回 `DrawObject`），房 `$18` 得 **58858**（68 fast / 76 full、48 行），与 trace 的 55308 差 3550（10×349 + 2×30）。只有「结构级 rts + 行截断」这一组合才精确等于 55308。复现方式：把 §5 脚本里 `if ab: break` 这一行删掉（守卫只丢本行、继续下一行），同一命令输出即变 58858。

**建议**（我不越权改已验收文档）：PMO 开一张 5 分钟卡，在 `docs/spec/room-load-cycles.md:116-128` 原地加【2026-11-27 更正，#135】注，把「最大行指针 `$6392` ⇒ 不触发」换成「两个对象进入属性区（`$63C0`/`$63DC`）⇒ 触发两次、少画 4 个 full」，并指向本文件。

## 5 复现

```bash
cd /home/peng/workspace/metroid-decomp
python3 - <<'PY'
from pathlib import Path
rom=Path('rom/Metroid (USA).nes').read_bytes(); prg=rom[16:16+0x20000]
base=lambda b:b*0x4000
def rd(b,a,n=1):
    o=base(b)+(a-0x8000); return prg[o:o+n]
def rd16(b,a):
    d=rd(b,a,2); return d[0]|(d[1]<<8)
def stream(b,a):
    o=base(b)+(a-0x8000); return prg[o:prg.index(0xFF,o)+1]
ROOM,STRUCT=0xA314,0xA372
def guard(p):
    hi=p>>8; lo=p&0xFF
    if hi<0x63: return False
    if hi in (0x63,0x67): return lo>=0xA0
    return hi>0x67
def objs_of(i):
    s=stream(1,rd16(1,ROOM+2*i)); pal=s[0]; j=1; objs=[]
    while s[j]!=0xFF:
        if s[j]==0xFE: j+=1; continue
        if s[j]==0xFD: j+=1; break
        objs.append((s[j],s[j+1],s[j+2])); j+=3
    en=0
    while s[j]!=0xFF:
        ty=s[j]&0xF
        if ty==1: en+=1; j+=3
        elif ty in (2,4): j+=2
        elif ty==6: j+=1
        elif ty==7: j+=3
        else: j+=ty if ty in (0,3,5) else 1
    return pal,objs,en
def run(i,BA=0x6000):
    pal,objs,en=objs_of(i); w=1300+9262+len(objs)*180+en*300
    fast=full=rows=0; st_naive=0
    for pos,si,opal in objs:
        st=stream(1,rd16(1,STRUCT+2*si)); idx=0; y=pos>>4; w+=20*y
        work=BA+y*0x40+(pos&0xF)*2
        while idx<len(st) and st[idx]!=0xFF:
            h=st[idx]; idx+=1; rows+=1; w+=30
            c=16 if (h&0xF)==0 else h&0xF
            rp=work+(h>>4)*2; ab=False
            while c:
                if guard(rp): ab=True; break
                if opal==pal: fast+=1; w+=214
                else: full+=1; w+=349
                idx+=1; rp=(rp+2)&0xFFFF
                if rp&0x1F==0: idx+=c-1; break
                c-=1
            if ab: break
            work=(work+0x40)&0xFFFF
    return w,len(objs),rows,fast,full
for i in (0x18,0x14,0x13,0x09,0x08):
    w,no,r,f,fl=run(i)
    print(f"room {i:#04x}: runtime_work={w} obj={no} rows={r} fast={f} full={fl}")
print("naive 0x18 =", 1300+9262+16*180+100*20+46*30+70*214+70*349+3*300)
print("diff =", (1300+9262+16*180+100*20+46*30+70*214+70*349+3*300)-run(0x18)[0])
```
