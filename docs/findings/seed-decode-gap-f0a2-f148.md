# findings：seed 解码缺口 $F0A2-$F148（数据岛实为代码）——分母错面

> 状态：**已证实**（2026-10-15，ROM 原字节级；复核员 2bb83775 发现 + 实施方自证）。
> 起因：「F162 无调用点」主张被复核证伪——该主张源于**扫描盲区**（见教训节）。

## 事实（A 级，ROM 原字节扫描）

- `bank07:$F109` 存在 `20 62 F1` = **JSR $F162**（直接调用点）；
- `$F0A2-$F148` 的 seed「数据岛」实为**连贯代码流**（自 seed 认可的 code 锚点 $F09F
  顺流解码；分支目标全落指令边界；`JMP $F09F`@$F0EA 回环=显式代码流）；
- 该区间内另有真实调用点（复核员+实施方 ROM 扫描并集）：`JSR $F152`@$F0A8、`JSR $F140`@$F0C9/$F0DF、
  `JSR $F1B3`@$F106、`JSR $F162`@$F109、`JSR $F1FA`@$F10C、`JSR $F186`@$F120/$F143/$F149、
  `JSR $F1BF`@$F140（另见 $F140 入口本身：JSR F1BF/JSR F186/JMP F1FA）；
- seed 将 F162-F172 / F1E7-F1EE 等解为数据 ⇒ 矩阵 **D-REG-07-036/038 错面登记**（data 面）。

## 影响

1. **分母错面**：S 面少计（未入 450 函数分母的真代码）、D 面多计（数据区混入代码）——
   D7「机械可导出」的分母受 seed 解码质量约束，此为**分母缺陷**显式入账；
2. F162/F1E7/F1EE 族是真代码 ⇒ batch-1 依赖链多出未登记单元（F140 组合例程等）；
3. 未知面：其余「数据岛」中是否还有真代码（系统性扫描工具待建）。

## 教训（扫描盲区第二案，r2 brace 同族）

「在 listing 上 grep 字节模式」≠「扫 ROM 原字节」——数据岛按字节**分行显示**，
`20 62 F1` 三字节永不连续出现 ⇒ grep 恒 0 = **假阴性**。任何 xref/调用点结论必须
以 **ROM 原字节扫描**为准（python 直接解析 prg 字节），listing grep 仅作线索。
