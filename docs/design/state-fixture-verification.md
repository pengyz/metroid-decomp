# design：状态夹具验证机制（state-fixture）——设计与对抗性审查记录

> 状态：设计稿 **v5**（2026-10-14）——v1→v4 四轮复审修正史与计数见 [rounds/r4](../rounds/r4-state-fixture-design-review.md)（唯一记账来源）。
> 背景：原版无即时存档（密码系统），能力验证需状态级置入。
> 符号约定（N5）：anchor 帧记 **F_a**（frame of anchor）；入局链的 A 键记 **(A 键)**——不再混用。

## 0. 问题与裁定

能力验证（跳跃弧线/变球/门/敌人接触）若每次从开机跑完整输入链：场景脆弱（G4 卡死态教训）
且「能力 × 状态」组合爆炸。用户思路（存档置状态→验能力；不行就自己实现）**方向正确**：
状态级行为验证是 L2（纯函数快照）与 L3 全帧对拍之间的缺失环节。

**四个陷阱**（T1-T3 用户自审 + T4 独立复核查出）；v2 复审另证伪 2 处过度声明（L2/L3），均已收窄。

## 2. 陷阱与修正（T1-T4）

### T1 人造状态 ≠ 可达状态
**修正**：① 夹具值从真实游戏证据导出；② 密码装载优先**当密码域覆盖经考证成立时**（§5）；
③ L5 可达性锚定机制（§5.1）；④ RAM 夹具限用于密码覆盖不到的态（位置/中间态）。

### T2 same-source 状态版（猜测地址 = 无意义验证）
**修正**：夹具每址带证据指针（A/B 级）；状态发现流程含**消融四件套**（§4.2）。

### T3 二进制 savestate 红线 / 跨侧不同源
入库边界不是「文本 vs 二进制」，是**策展元数据（最小写集 + 逐址证据指针）vs 批量机器输出**
（trace/ram.hex 整页 dump 虽是文本亦不入库）。夹具入库判据：**最小（或有上限的策展）写集 +
逐址证据指针 + 禁止整页 dump + source_evidence 只存指针不存 diff 本体**。
类别差异：夹具值=运行时观测导出（**须消融确认——证据链要求比 l2 golden 更严一级**）；
l2 golden=静态反汇编手推。savestates 仅作发现工具（analysis/，不入库）。

### T4 注入点时序竞争 + 状态域完备性
- **帧 0 写不可行**：机器刚过 RESET 走 boot/标题/入局链，新游戏初始化**必然重写**能力/道具
  RAM；绕过 boot 伪造模式字节 = 重新掉进 T1。（G4 A1 证据。）
- **写清单 ≠ 机器状态**：oracle 在注入点是完整机器（MMC1/PPU/APU/RNG/敌人槽/派生缓存）。
**修正**：§3 F_a 注入模型 + 三条件断言（同源证明义务）。

## 3. 注入模型（anchor 帧 + 同链重放 + 三条件断言）

```
① 入局链重放      两侧（oracle / game-core）跑**同一入局输入链**
                  （title→start→(A 键)→start，G4 A1 验证序列）至 anchor 帧 F_a
                  （F_a 判据**机械化**，见下）
② anchor 写入     夹具 writes 在 F_a 帧执行：
                  oracle = emu.write（step 0 探针验证语义）；game-core = 同一 JSON 构造
③ 同源断言（三条件，L2/D1/G1/v5 F1-F3 修正）：
   能力窗口 = [F_a+1, F_a+k_max]（k_max=窗口**长度**，case 声明默认 120；读回点=F_a+k_max——
   单符号口径，v4 的 k_window 双义已废，见 rounds/r4）。
   (a) F_a+1 帧状态向量全等（watch **声明域内**逐字节——仅证「声明域内、F_a+1 采样时刻」
       同源，不证 F_a 时刻、不证域外、不证 F_a+2 之后）；
   (b) **写入地址采样一致性**：写入地址在 F_a+1 的值 == 夹具期望值
       （点时刻「值在场」——非因果证明，L-1 命名收窄；防「共同被覆盖假同源」）；
   (c) **持续性后置（G1/v5 F2 修正）**：**仅 invariant 地址**在窗口末帧 F_a+k_max 读回
       == 夹具期望值。夹具逐址标 `persistence: invariant | evolving`：invariant=能力标志类
       （应持续在场）；evolving=位置/朝向/当前能量/动画相位类（能力行为合法改变它们——
       起点存活由 (b) 覆盖，演化本身正是能力验证的观测量）。防「F_a+2 起共同同速覆盖」
       导致夹具静默死亡；B-SCN「能力×状态」covered 声明以 invariant 部分 (c) 通过为前提。
   **落点/侧别（v5 F3）**：(a)(b)(c) 均由 L3 比对器执行（diff_traces 的 fixture 扩展，
   **待实现**），(a)(b) 即时门（F_a+1）、(c) 后置门（窗口末判定——期间场景继续跑，
   最终结果以 (c) 终判）；(a) 跨侧、(b)(c) 双侧各自读回均检。
   (a)(b) 不满足即 FAIL 不得带病继续；(c) 见 §6 分流。F_a+2 及以后分叉见 §6 溯源路由。
④ 能力验证        F_a+1 起按场景输入验证行为（L3 逐帧对拍）
```

**F_a 判据（L8 修正，可机械判定）**：冻结输入链（start@360 + a@420 + start@540，场景帧计数自
RESET 起算）下 **绝对帧 f≥800 ∧ OAM 玩家精灵在场**（OAM 谓词=G4 部分操作化：OAM 表存在 y≠$F0 的玩家条目——**C 级假设**，
findings A1/A4 无 OAM 结构证据支撑，待 A 级 OAM dump 取证；「哪条=Samus」签名由 **step 0 认领**
（清单见 §7）；钉死前按「OAM 有非隐藏精灵条目」机械执行，弱化点显式声明）。
证据指针：docs/findings/samus-movement-observations.md A1/A4；场景 `oracle/scenarios/samus-move3.txt`；
`analysis/traces/samus-move3.frames.jsonl`。（v2 措辞「解锁后再数 800 帧」与证据窗口矛盾，已更正为
绝对帧判据。）

**密码链（N2）**：密码装载路径的入局链（密码屏输入链）≠ 标准链，其 F_a 判据在密码场景中
**单独声明**（锚定语义同 §5.1）。

**状态域声明**：夹具域 = CPU RAM `$0000-$07FF`（显式基址区间，含栈页——不用惯常分区假设，
gotcha-stack-page 两次教训）。域外（mapper/PPU/APU 态）由共同历史**弱近似**（两侧同链重放到 F_a，不证域外全等——
正因不充分才有 §6 的域审查兜底）；
判定与路由见 §6（A+k 溯源）。

## 4. 状态发现流程

```
① 真实证据获取：输入链走到状态获取点（savestate 辅助定位时刻，不入库）
② 前后 diff：状态获取前后 RAM 帧级 diff → 候选地址集（A 级动态证据）
③ 消融四件套（均 A 级动态证据）：
   a. 集合充分：全集写入「无该状态」基线 → 行为翻转
   b. 单址必要：从「有状态」态移除单址 → 行为回退（逐址因果）
   c. 最小性：无真子集可翻转（不可分割联合集 → 整集登记并标注联合语义）
   d. 负对照：等尺寸随机写集 → 行为不翻转（排除幻觉翻转）
④ 假阴性处置：派生状态（换房/装载时才重算）缺失导致消融阴性 ≠ 因果否定——
   记入待查，换上下文重试；相关非因果地址（如 H2 疑影子对）按 b/c 剔除
⑤ 夹具登记：source_evidence 只存指针（场景 id / trace sha / 消融记录 id）
```

> 【2026-10-14 更正】v1 写「消融=行为级确认因果，非仅相关」——措辞过强，已收回：四件套证明
> 的是（集合充分 + 单址必要 + 最小 + 负对照通过）范围内的因果主张，非绝对因果。

## 5. 密码装载 vs RAM 夹具

| 维度 | 密码装载（原生状态装载器） | RAM 夹具 |
|---|---|---|
| 可达性（T1） | ✅ 原生无懈可击（游戏自带合法路径） | ⚠ 须消融+可达性锚定 |
| 红线（T3） | ✅ 纯文本（密码字符串） | ✅ 策展写集（§2 T3 判据） |
| 覆盖面 | 能力/物品/进度组合——**待证（编码未逆向；位掩码/枚举表结构决定可表达空间；不编码当前位置/朝向/动画相位/敌人槽等）** | 位置/朝向/中间态/动画相位 |
| 两侧消费 | game-core 需密码模块（见下 L7 排期） | 需注入机制 |
| 依赖 | 需先逆向密码编码（S3 模块） | 需状态发现流程 |

**分层结论（带条件）**：密码编码逆向**证实可表达能力/物品组合后**，密码装载优先覆盖该域；
RAM 夹具补位置/中间态。在考证完成前，两者并行、不预设优先。

**依赖与降级（L7）**：密码装载的差分消费要求两侧能装载——oracle 侧免费，game-core 侧需密码
模块。密码模块按 [north-star.md](../north-star.md) M4（全内容阶段）排期，**晚于 M2 首切片需求**
⇒ 关键路径先行的是 RAM 夹具。**降级触发器**：S3 密码逆向若在 M2 收口前未交付（或编码考证
否定组合覆盖面）⇒ 能力验证全走 RAM 夹具 + L5 锚定，密码装载转 M4 后补强项。
（仓库级待办：north-star.md 与 methodology.md 里程碑编号矛盾——已登记 master-plan。）

### 5.1 可达性锚定机制（L5 腿）
- 判据（L-2 修正，**跨轨**比较）：夹具跑（链+F_a 写入）的能力窗口**声明域内**轨迹 == 真实可达跑
  （纯输入链到达「同状态」=域内写集相等）的域内轨迹——比较对是「夹具跑 vs 真实链跑」，不涉跨侧；
  跨侧的 F_a+1 断言另见 §3③。
- 优先级：关键路径夹具先行（G4 首切片 → Boss 链路），边缘组合挂 B 面场景增长；
- 密码可达的态由密码装载路径满足锚定（密码域考证成立后免费）。

## 6. 与既有机制衔接

| 接口 | 约定 |

| **runner/DSL 接口（D4）** |（以下均**待实现**）scenario DSL 增 `fixture <id>` 指令（scenario_run 解析 → scenario_capture 于 F_a 帧执行写入）；`fixture_sha256` 校验方 = diff_traces（case 携带）；同源三条件断言落点 = diff_traces fixture 扩展（(a) 跨侧、(b)(c) 双侧读回；(c) 为窗口末后置门）——待实现 |

| **分类路由**（pipeline §4.2 现行 6 类；夹具类=第 6 类） | **失败分流（机械，L1/G2/G3/L-3 修正）**：① 无夹具基线（同链裸跑）**全能力窗口**比对先行——基线红 ⇒ **转 §4.2 常规分类**（移植错/参考bug/投影错/平台差异——不进夹具维护；F14 修正：不塌缩为单类）；② 基线绿 + 带夹具红：首分歧帧=F_a+1 ⇒ 同源断言失败→夹具维护（重走状态发现）；首分歧帧∈(F_a+1, F_a+k_max] ⇒ **域审查**（角色 decomp-analyst，产出=域扩展或降级 L5 裁定）→ 按裁定路由；首分歧帧>F_a+k_max ⇒ 查 (c) invariant 地址读回：读回失败⇒夹具维护，读回成功⇒转 §4.2 常规分类（含参考bug/投影错/平台差异）。fixture sha 不符 / 帧集不一致 ⇒ 夹具维护（无首分歧帧可判时的显式分支，F6）。**定义（可机械）**：漂移帧=diff_traces 首分歧帧；k_max=case 声明的能力观察窗口长（默认 120 帧）；窗口末帧=F_a+k_max（k_window 符号已废） |

**过渡期（D5，S5 前）**：game-core 腿未就绪 ⇒ 夹具场景单侧运行，标注 **proof-pending**
（同源三条件断言未执行）；S5 后补验通过方可计入 B 面 covered。

## 9. 风险登记

- 夹具值腐化 → manifest sha 对锚 + 重基线证据强制（§6）；
- 状态组合爆炸 → 密码域考证后分层吸收 + 夹具按关键路径优先；
- emu.write 语义未知 → step 0 探针硬前置（含写序/时序钉死）；
- 域外状态分叉 → 三条件断言 + A+k 溯源路由 + 域扩展/降级二选一；
- 密码逆向延期 → 降级触发器（§5）。
