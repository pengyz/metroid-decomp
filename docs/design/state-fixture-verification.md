# design：状态夹具验证机制（state-fixture）——设计与对抗性审查记录

> 状态：设计稿 **v2**（2026-10-14）——v1 经独立复核 needs_revision（6 项修正，见 §8），
> 本版为修正稿。背景：原版无即时存档（密码系统），能力验证需状态级置入。

## 0. 问题与裁定

能力验证（跳跃弧线/变球/门/敌人接触）若每次从开机跑完整输入链：场景脆弱（G4 卡死态教训）
且「能力 × 状态」组合爆炸。用户思路（存档置状态→验能力；不行就自己实现）**方向正确**：
状态级行为验证是 L2（纯函数快照）与 L3 全帧对拍之间的缺失环节。

**但 v1 有四个陷阱**（T1-T3 用户自审 + T4 独立复核查出），修正见 §2-§4。

## 1. 事实基线（不变）

| 侧 | 随时存档 | 机制 |
|---|---|---|
| 原版游戏 | ❌ 即时存档；✅ **密码系统是原生状态装载器**（见 §5 取舍表） | 密码编码进度/能力/物品组合 |
| oracle（Mesen2） | ✅ | savestates（发现工具）；Lua `emu.write`（**语义待 step 0 探针**） |
| game-core（Rust） | ✅ | 状态构造是第一公民 |

## 2. 陷阱与修正（T1-T4）

### T1 人造状态 ≠ 可达状态
**修正**：① 夹具值从真实游戏证据导出；② **密码装载优先**（原生可达，T1 无懈可击，§5）；
③ L5 可达性锚定给出机制（§5.2）；④ RAM 夹具限用于密码覆盖不到的态（位置/中间态）。

### T2 same-source 状态版（猜测地址 = 无意义验证）
**修正**：夹具每址带证据指针（A/B 级）；状态发现流程含**消融四件套**（§4.2）。

### T3 二进制 savestate 红线 / 跨侧不同源
**修正（v2 口径重写）**：入库边界不是「文本 vs 二进制」，是
**策展元数据（最小写集 + 逐址证据指针）vs 批量机器输出**（trace/ram.hex 整页 dump 虽是文本亦不入库）。
夹具入库判据：**最小（或有上限的策展）写集 + 逐址证据指针 + 禁止整页 dump + source_evidence
只存指针不存 diff 本体**。注意类别差异：夹具值=运行时观测导出（须消融确认），
l2 golden=静态反汇编手推——证据链要求更严一级。
savestates 仅作发现工具（analysis/，不入库）。

### T4（v2 新增，独立复核查出）注入点时序竞争 + 状态域完备性
- **帧 0 写不可行**：机器刚过 RESET 走 boot/标题/入局链，新游戏初始化**必然重写**能力/道具
  RAM；绕过 boot 伪造模式字节 = 重新掉进 T1。（G4 A1 证据：`title→start→A→start` 链 +
  解锁确认后 ≥800 帧才可用——设计 v1 自己的事实基线反证了帧 0 注入。）
- **写清单 ≠ 机器状态**：oracle 在注入点是完整机器（MMC1 bank/移位寄存器态、PPU 滚动/
  nametable/CHR-RAM 进度、APU、RNG、敌人槽、派生缓存）；单写夹具两侧必然分叉。
**修正**：§3 anchor 帧注入模型 + A+1 状态向量全等断言（同源证明，不是「天然成立」）。

## 3. 注入模型（v2 重写：anchor 帧 + 同链重放）

```
① 入局链重放      两侧（oracle / game-core）跑**同一入局输入链**
                  （title→start→A→start，G4 A1 已验证序列）至 anchor 帧 A
                  （A = 入局完成判据帧：解锁确认后 ≥800 帧——判据挂在 G4 证据上）
② anchor 写入     夹具 writes 在 A 帧执行：
                  oracle = emu.write（step 0 探针验证语义）；game-core = 同一 JSON 构造
③ 同源断言        **A+1 帧状态向量全等**（watch 全域逐字节）——两侧分叉即 FAIL，
                  不得带病继续（这是「同源起点」的证明义务）
④ 能力验证        A+1 起按场景输入验证行为（L3 逐帧对拍）
```

**状态域声明**：夹具域 = CPU RAM `$0000-$07FF`（显式地址区间，含栈页——不用「zp+iram」
惯常分区，gotcha-stack-page 两次教训）。域外（mapper/PPU/APU 态）由**共同历史保证**
（两侧同链重放到 A）；若某能力行为依赖域外状态且共同历史不充分 ⇒ 该夹具**不成立**，
改走域扩展（夹具 schema 升级声明 mapper 态）或降级 L5——二选一，不默认「无关」。

## 4. 状态发现流程（v2 修正）

```
① 真实证据获取：输入链走到状态获取点（savestate 辅助定位时刻，不入库）
② 前后 diff：状态获取前后 RAM 帧级 diff → 候选地址集（A 级动态证据）
③ 消融四件套（均 A 级动态证据——v2 修正 F4 口径）：
   a. 集合充分：全集写入「无该状态」基线 → 行为翻转
   b. 单址必要：从「有状态」态移除单址 → 行为回退（逐址因果）
   c. 最小性：无真子集可翻转（不可分割联合集 → 整集登记并标注联合语义）
   d. 负对照：等尺寸随机写集 → 行为不翻转（排除幻觉翻转）
④ 假阴性处置：派生状态（换房/装载时才重算）缺失导致消融阴性 ≠ 因果否定——
   记入待查，换上下文重试；相关非囚果地址（如 H2 疑影子对）按 b/c 剔除
⑤ 夹具登记：source_evidence 只存指针（场景 id / trace sha / 消融记录 id）
```

> 【2026-10-14 更正】v1 写「消融=行为级确认因果，非仅相关」——**措辞过强**，已收回：
> 四件套证明的是（集合充分 + 单址必要 + 最小 + 负对照通过）范围内的因果主张，非绝对因果。

## 5. 密码装载 vs RAM 夹具（v2 新增，F6 修正）

| 维度 | 密码装载（原生状态装载器） | RAM 夹具 |
|---|---|---|
| 可达性（T1） | ✅ **原生无懈可击**（游戏自带合法路径） | ⚠ 须消融+可达性锚定 |
| 红线（T3） | ✅ 纯文本（密码字符串） | ✅ 策展写集（v2 判据） |
| 覆盖面 | 能力/物品/进度**组合** | 位置/朝向/中间态/动画相位 |
| 两侧消费 | game-core 反正要实现密码模块（M4）≈ 免费 | 需注入机制 |
| 依赖 | 需先逆向密码编码（S3/S4 模块） | 需状态发现流程 |

**分层结论**：**密码装载优先**覆盖能力/物品组合类验证；RAM 夹具补密码表达不了的态
（位置/中间态）。密码逆向（bank 图 + 编码考证）纳入 S3 计划——它同时解锁 M4 密码模块与
本机制的大半需求。

### 5.1 可达性锚定机制（L5 腿，F6 修正）
- 判据：夹具状态 = **存在一条真实输入链**在 anchor 帧达到同状态（A+1 状态向量全等）；
- 优先级：关键路径夹具先行（G4 首切片 → Boss 链路），边缘组合挂 B 面场景增长；
- 密码可达的态直接由密码装载路径满足锚定（免费）。

## 6. 与既有机制衔接（v2 新增，F7 修正）

| 接口 | 约定 |
|---|---|
| **fixture manifest** | `oracle/fixtures/<name>.json` 含 `id`/`writes`（逐址 why+证据指针）/`source_evidence`/`anchor`（链+帧 A 判据）；**sha256 入 l3_manifest 的 case**（case 增 `fixture_id` + `fixture_sha256`）；夹具值变更 ⇒ 相关 l3 case 重基线（manifest sha 链留痕） |
| **完备性矩阵** | 夹具 L3 场景入 **B 面分母**（B-SCN-* 格）；「能力×状态」可枚举=**声明性、语料驱动的可枚举**（D7 口径，不重造绿=完整错觉）；金字塔轴=L3，矩阵 strength 轴=L3 对拍过（两轴不混） |
| **四分类路由** | 补第五类：**夹具失效/腐化**（A+1 同源断言 FAIL、manifest sha 不符）→ 路由「夹具维护」=重走状态发现流程；不进 porter/spec 调试循环 |

## 7. 实施顺序（v2 重排，F8 修正）

0. **step 0 注入点+emu.write 语义微探针**（execute 回调教训：API 能用≠语义对）：
   帧 0 vs anchor 帧各写已知值 → 读回 + 被覆盖观察 + 写入帧相位——**F1 的答案在此产出**
1. fixture DSL + anchor 注入模型（含 A+1 同源断言）落地
2. 密码系统逆向立项（S3，解锁密码装载 + M4）
3. **首例夹具选简单态**（单地址、行为差异大、语义已 A 级——如能量值），变球（捆绑最难
   注入点+最难语义 H2/H3）排后
4. 夹具 × 能力场景库模板（l3 case fixture 字段 + manifest 钩子）
5. game-core 侧消费接口（S5）

## 9. 风险登记（v2 更新）

- 夹具值腐化 → manifest sha 对锚 + 夹具失效路由（§6）；
- 状态组合爆炸 → 密码装载分层吸收 + 夹具按关键路径优先；
- emu.write 语义未知 → step 0 探针硬前置；
- 域外状态分叉 → A+1 断言硬闸 + 域扩展/降级 L5 二选一。
